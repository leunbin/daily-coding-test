# Daily Coding Test

Java 백엔드 코딩 테스트 대비를 위한 **매일 1문제** 학습 기록입니다.

## 학습 규칙

- 매일 오후 8시에 GitHub Issue로 등록되는 문제 1개를 풉니다.
- 최소 성공 기준은 **접근법 정리와 풀이 커밋 1개**입니다.
- 코드를 작성하기 전에 접근법과 시간·공간 복잡도를 먼저 정리합니다.
- 30분 이상 막히면 힌트를 확인하되, 정답을 본 문제도 직접 다시 구현합니다.
- 주제는 구현부터 시작해 코딩 테스트 전 범위를 순환합니다.

```text
구현 → 문자열 → 배열·해시 → 스택·큐·덱 → 정렬 → 완전탐색
→ 투 포인터·슬라이딩 윈도우 → 누적합 → BFS·DFS → 백트래킹
→ 힙 → 그리디 → 이진 탐색 → 그래프(최단 경로·MST·위상 정렬·Union-Find)
→ DP → 비트마스킹
```

## 디렉터리 구조

```text
solutions/
└── YYYY-MM-DD/
    ├── README.md
    └── Main.java
```

## 문제 풀이 순서

1. GitHub Issue의 문제와 제약 조건을 읽습니다.
2. 날짜별 `README.md`에 접근법과 복잡도를 먼저 작성합니다.
3. `Main.java`로 풀이합니다.
4. 예제와 경계값을 확인합니다.
5. 틀린 이유와 다음에 기억할 점을 기록합니다.
6. 문제별 브랜치에 커밋하고 Pull Request를 생성합니다.
7. 리뷰를 반영한 뒤 `main`에 머지합니다.

## 커밋 메시지 규칙

기본 형식은 다음과 같습니다.

```text
<type>: YYYY-MM-DD 변경 내용 (#이슈번호)
```

| Type | 사용 시점 | 예시 |
| --- | --- | --- |
| `solve` | 문제 풀이 완료 | `solve: 2026-10-28 문제 풀이 (#1)` |
| `fix` | 오답 또는 버그 수정 | `fix: 2026-10-28 경계값 처리 수정 (#1)` |
| `refactor` | 동작을 유지하며 코드 개선 | `refactor: 2026-10-28 리뷰 반영 (#1)` |
| `test` | 테스트 케이스 추가·수정 | `test: 2026-10-28 경계값 테스트 추가 (#1)` |
| `docs` | README 등 문서 수정 | `docs: 커밋 메시지 규칙 추가` |

Issue를 머지와 함께 자동으로 닫으려면 PR 본문에 다음 문구를 작성합니다.

```text
Closes #이슈번호
```

## 자동 검사

`solutions` 아래의 모든 Java 파일은 push 및 pull request 시 GitHub Actions에서 Java 21로 컴파일됩니다.
